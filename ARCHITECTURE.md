## Authentication flow

1. `/register` → `POST /api/user/` (AllowAny). Backend creates user with
   `email_confirmed=False` and queues a confirmation email.
2. User clicks the link → `/user/confirm-email/:uid/:token` →
   `POST /api/user/email/confirm/`. Backend flips `email_confirmed=True`.
3. `/login` → `POST /api/token/`. Backend returns
   `{access, refresh}`. The `EmailConfirmedTokenObtainPairView` refuses
   tokens for unconfirmed emails.
4. The `auth-interceptor` attaches `Authorization: Bearer <access>` to every
   request. On `401`, it deduplicates concurrent refreshes, calls
   `POST /api/token/refresh/`, and replays the original request.
5. Logout clears in-memory tokens and blacklists the refresh token.

The access token lives in memory only (XSS hardening). The refresh token is
persisted in `localStorage` (with "remember me") or `sessionStorage`.

## Email outbox pattern

`core.mailers._common.queue_email()` writes an `OutboundEmail` row instead
of calling `EMAIL_BACKEND` synchronously. The Celery beat task
`deliver_outbound_emails_task` (every 60s, see
`config.settings_base.CELERY_BEAT_SCHEDULE`) drains pending rows.

Why: the request handler stays fast and resilient — SMTP outages don't
break user-facing flows, and bursts smooth out across the worker pool.

## OpenAPI sync

`scripts/sync-openapi.ps1`:

1. Calls `python manage.py spectacular --file openapi.yaml`
2. Copies the YAML to the frontend
3. Runs `npx openapi-generator-cli generate` to regenerate
   `src/app/api/generated/`

Run after any DRF serializer/view change. CI verifies the generated client
is up to date (see `.github/workflows/ci.yml`).

## Deploy pipeline

1. **Build (CI)**: `.github/workflows/deploy.yml` triggered on push to
   `main`. CI builds the Angular bundle (the EC2 instance is too
   memory-limited for `ng build`).
2. **Ship**: SCP the bundle to the server.
3. **Apply**: SSH and run `deploy/redeploy.sh`, which:
   - `git pull`
   - `pip install -r requirements.txt`
   - `python manage.py migrate`
   - `python manage.py collectstatic --noinput`
   - Auto-detects nginx vs apache, reloads
   - `sudo systemctl restart` for gunicorn/celery/celery-beat services
   - Health check via `curl` against `/health/`

Required NOPASSWD sudoers entry for the `django` user — see comments inside
`redeploy.sh`.
